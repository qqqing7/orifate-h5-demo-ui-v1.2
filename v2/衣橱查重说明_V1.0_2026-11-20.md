# 衣橱查重说明（V2 首版：图片哈希 + 品类颜色指纹 + 软提示）

> 版本：V2-日历优先 · 2026-11-20
> 目的：同一件衣服被不同照片重复上传时，给用户一个提示，避免衣橱里出现两条一样的记录。

---

## 1. 问题是什么

衣橱里「同一件衣服」可能被传两次，而两次的**照片不一样**：重拍、换角度、截图、压缩后重存……文件名、尺寸、字节都不一样，系统无法用「图片是否相同」直接判断。

所以首版拆成两层判断：

1. **同一张照片**（图片内容几乎一样）→ 能自动认出来；
2. **同一件衣服的不同照片** → 用「品类 + 颜色」这组文字特征近似判断；
3. 命中任何一层，都只**弹提示**，由用户决定是否合并。

---

## 2. 首版做了什么

### 2.1 图片感知哈希（判断「同一张照片」）

- 把图片缩成 **8×8 灰度**，取平均值，逐像素比较得到 **64 位** 0/1，再转成 **16 位十六进制** 字符串，存到 `Garment.imageHash`；
- 再次上传时计算新图的哈希，与衣橱里每一件的哈希比 **汉明距离**；
- **距离 ≤ 5（共 64 位）** → 判定为「同一张照片」。

能覆盖：同一张图反复上传、裁剪过、压缩过、改过尺寸、截图重存。
成本：纯前端 canvas，无网络请求，几十毫秒。

### 2.2 品类 + 颜色指纹（判断「同一件衣服的不同照片」）

- 指纹 = `服饰类别 | 归一化颜色`；
- 颜色归一化：去空格、去掉结尾的「色」、英文转小写（`米白色 ` → `米白`）；
- **同类别 + 同归一化颜色** → 判定为「品类和颜色相同」。

颜色从哪来：V2 接了衣物识别时由 Dify 自动预填；没接识别时用你在「确认衣物」页手填的颜色。

### 2.3 软提示弹层

命中任一层，保存时弹底部弹层：

- 标题「衣橱里可能已有这件」，副标题写明原因（同一张照片 / 品类和颜色相同）；
- 并排展示两张图：**衣橱里** vs **这次上传**，方便肉眼确认；
- 三个动作：
  - **是同一件，合并** → 用这次的照片替换旧记录，不新增；
  - **不是，仍然新增** → 正常新增一条；
  - **取消** → 不保存，留在「确认衣物」页继续改。

**永远只提示、不硬拦**：同色同款真有两件（比如两件白衬衫）很常见，硬拦会挡住正常操作。

---

## 3. 三种动作的数据行为

| 动作 | 实际发生什么 |
| --- | --- |
| 是同一件，合并 | 保留旧记录的 `id`（穿搭记录/方案里对它的引用不断），把 `image`、`imageHash`、`color` 换成这次的；`brand / size / fabric` 有值才覆盖；衣橱总数不变 |
| 不是，仍然新增 | 新建一条独立记录，两条并存 |
| 取消 | 不写入，停在「确认衣物」页，可改颜色/类别或换图后再存 |

---

## 4. 判定顺序与阈值

```
保存 → 计算哈希（失败则跳过图片判断，不阻断保存）
      → 扫描衣橱：哈希距离 ≤ 5 ？ 命中「同一张照片」并弹窗
      → 未命中：品类 + 归一化颜色相同 ？ 命中「品类和颜色相同」并弹窗
      → 都未命中：直接保存
```

| 判断 | 阈值 | 说明 |
| --- | --- | --- |
| aHash 汉明距离 | ≤ 5 / 64 | 越小越严；≤5 基本只会命中同图或裁剪版，正常不同照片不会被误判 |
| 颜色 | 归一化后**精确相等** | 暂不做近似（「米白」和「奶白」算不同） |
| 类别 | 精确相等 | 类别来自下拉，天然一致 |

---

## 5. 能覆盖什么、覆盖不到什么

**能覆盖**

- 重复点「加入已有」；
- 同一张图再传一次；
- 同一张图裁剪 / 压缩 / 改尺寸后重传；
- 同一件衣服换了照片，但品类和颜色（手填或识别）填得一致。

**覆盖不到（已知局限）**

- 同款不同色（黑/白两件）→ 判为不同，这是对的；
- 近色（米白 vs 奶白）→ 判为不同，会漏提示；
- 换角度、换光线、且颜色填得不一样 → 两层都命中不了；
- 衣橱里的老数据没有 `imageHash` → 只参与指纹比较，图片层不判断；
- 真有两件同色同款 → 会误报一次，选「不是，仍然新增」即可（不阻断）。

## 6. 后续可以继续做（按性价比排序）

1. **近似颜色**：颜色转 Lab 算色差，ΔE ≤ 6 视为同色，减少「米白/奶白」漏判；
2. **识别补 colorHex**：V2 的衣物识别工作流目前只返回颜色名，补一个主色 hex 后，指纹可升级为「类别 + 主色 ΔE」；
3. **视觉相似度**：图片 embedding（CLIP 类）余弦相似度 > 0.85 提示；或在 Dify 里加一个「衣物查重」工作流（新图 + 候选 3 件主图 → 输出 same / different），这是唯一能真正判断「同一件衣服」的方案；
4. **衣橱「整理」入口**：按 品类+颜色 分组，≥2 件时给「合并」按钮，批量清理历史重复；
5. **多图上传时询问**：「这几张是同一件（合并成一条多图），还是分别添加？」——图片哈希只能判断「是不是同一张」，判断不了「是不是同一件」，所以交给用户选择。

## 8. 兼容性与迁移

- `imageHash` 是**可选**字段，老数据不需要迁移；老衣物没有哈希时只参与指纹比较；
- 存储 key 没变（`orifate.uni.demo.v2`），不会清空现有衣橱；
- 目前只在 H5（浏览器 `canvas`）验证；如果以后要跑小程序，`imageHashOf()` 需要改成 uni 的 canvas 方案，或者小程序端只保留「指纹」这一层。

## 9. 已验证的四种情况（V2，2026-11-20）

| 场景 | 结果 |
| --- | --- |
| 第一次上传（图 A，上衣/米白） | 直接保存，衣橱 1 件 |
| 再传**同一张图 A**（上衣/米白） | 弹「同一张照片」，选合并 → 仍是 1 件 |
| 再传**同一张图 A** | 弹「同一张照片」，选仍然新增 → 2 件 |
| 传**另一张图 B**（上衣/米白） | 弹「品类和颜色相同」，取消后改成黑色再存 → 3 件 |

---

## 10. 一句话总结

首版用「图片哈希（同图）+ 品类颜色指纹（同款）+ 只提示不拦截」覆盖了最常见的重复上传，把「是不是同一件」的最终判断留给用户；真正的跨照片识别留到后续接识别/相似度模型时再做。
