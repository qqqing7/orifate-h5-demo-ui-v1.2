## v1.2 相对 v1.1 的变化

**交互与功能统一到 V2 标准（六个版本一致）**

1. **色彩分析只有一条路径**：入口 → 拍照/相册 → 确认照片 →「照片可以分析」→ 补答六题 或 直接看初步结果 → 结果。删除了「选择分析方式 / 色彩初步解析 / 核对色彩特征 / 18 题题卡 / 问卷结果页」。
2. **体型分析只保留手工输入**：删除拍照体型（拍摄 / 确认体型照片）、身高与正侧面照逻辑。
3. **我的页**：穿搭记录（我的穿搭方案 / 穿搭日历）+ 分析记录（色彩分析 / 体型分析）；删除「推荐穿搭记录 / 聊天记录与收藏 / 偏好设置（语言偏好）/ 隐私数据」，无会员。
4. **我的穿搭方案**：列表（场景筛选、来源标记、日期、衣物）+ 详情 + 删除；穿搭方案页改为「保存到我的穿搭方案」并跳转。
5. **衣橱导入**：只留「拍照」和「从相册选择照片」，删除线上搜索 / 购物订单 / 邮件收据 / 单图多件拆分入口。
6. **首页分析入口做完即收起**（判定统一：色彩有可用结果、体型有成功分类）；入口仍可从「我的」进入。
7. **V1 首页近 7 天**：点某天只选中（有描边高亮），按钮变为「＋ 记录所选日期」，按所选日期记录。
8. **V2 新增衣橱查重**：上传时用「图片感知哈希 + 品类颜色指纹」判断疑似重复，弹窗提供「合并 / 仍然新增 / 取消」，只提示不硬拦。详见 `v2/衣橱查重说明.md`。

**每个版本独立存储**

各版本的 localStorage key 前缀不同（`orifate.uni.demo.v12-<版本>:`），同一域名下互不干扰，填生日/记录不会串版本。

## 部署到 GitHub Pages

### 方式 A：GitHub Actions（推荐）

1. 新建仓库；
2. 把**本文件夹里的全部内容**上传到仓库根目录（不是把 `V1.2` 再套一层）；
3. 仓库 `Settings → Pages`，`Build and deployment` 选 **GitHub Actions**；
4. 推送 `main` 后 `.github/workflows/pages.yml` 会自动部署。

### 方式 B：从分支部署

`Settings → Pages → Deploy from a branch`，选 `main` 和 `/ (root)`。

## 本地预览

任何静态服务器即可，例如：

```bash
npx serve .
# 或
python -m http.server 8000
```

然后打开 `http://localhost:8000/`。

## 说明

- 除 V2 的颜色分析 / 推荐 / 衣橱识别外，其余全部在浏览器本地完成，不上传照片、不连后端；
- V2 要完整使用 Dify 能力，请按项目 README 在本地启动 `server/`（`npm run build:h5:local` + `node server/index.mjs`），静态包只用于预览界面；
- 所有数据只保存在当前浏览器 localStorage，换浏览器/清缓存即清空。
